## 2024-05-15 - Memoizing Leaf Components in React NextJS Tables
**Learning:** This application heavily uses `ProviderIcon` component across multiple list and table views (e.g., `UsageTable`, `ProviderTopology`, `ProviderLimits`, `TopModelsChart` usage). Since these lists frequently re-render (e.g. from usage stats polling or user interactions expanding tables), any pure leaf components in these rows that only receive primitive props (like strings for `src`, `providerId`, `size`) are prime candidates for `React.memo()`. Without `memo()`, every row update unnecessarily recreates these icons.
**Action:** Always identify pure leaf components rendered inside `map()` blocks and tables. If they only take primitives and are ubiquitous, wrap them in `React.memo()` to cut down on render loop overhead.
